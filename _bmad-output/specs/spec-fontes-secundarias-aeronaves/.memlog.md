- (decision by user) Allow non-official technical values because the software is purely didactic: “este software é puramente didatico para desenvolvimento de software pode ser usado dados nao oficiais”.
- (constraint) Every secondary value must have a traceable source, unit, publication/access date and stated model applicability; label it as a didactic estimate and never present it as validated for real flight.
- (question) When AOPA, Pilot-Next, Aeroway or other traceable sources disagree, which source priority should select the didactic value? Until settled, do not silently average conflicting values.
- (event) Amended project constitution to v4.0.0 on 2026-11-24 to allow sourced secondary values for didactic calculations with visible estimates and non-operational warning.
- (assumption) Use the most model/variant-specific traceable source; if comparable values conflict, label them disputed and keep the affected field unavailable until resolved, never average.
- (capability) CAP-1: Team can offer small-airplane models with traceable official or secondary data for didactic exercises; success means every required field has unit/source/publisher/date/applicability and all secondary values are labeled in UI, result and PDF.
- (constraint) Required fields remain usable fuel, nominal-profile cruise speed and matching fuel burn, empty weight, approved MTOW and baggage limit; no invented, copied or interpolated values.
- (constraint) Preserve small-airplane PMD <=5,670kg, count only current RAB CD_INTERDICAO=N, filter complete models before limiting to 30, and hide incomplete models.
- (decision) The new source rule supersedes only the official-source requirement in the catalog spec; all remaining catalog and route requirements remain.
- (non-goal) Do not make the application an operational flight-planning, dispatch, or flight-authorization tool; secondary-data outputs are not valid for real-world flight decisions.
- (direction by user) Initial research leads: AOPA Aircraft Fact Sheets, Pilot-Next fuel-burn comparisons, Aeroway fuel-burn/capacity calculator; FAA remains an official regulator source. URLs are captured in secondary-sources.md and are not yet independently verified for variant coverage.
- (assumption) Prefer official sources when available, but secondary sources are allowed; choose the most specific applicable source and never present it as officially validated.
- (event) Self-validation pass 1 (coherence): passed; CAP-1 has intent/success, constraints bend behavior, non-goals and measurable success signal are present, assumptions are explicit.
- (event) Self-validation pass 2 (preservation): passed; user intent to use traceable secondary data for didactic software, preserve the 30-model/RAB-N/VFR limits, and retain the suggested source list are present in SPEC.md or its companion.
- (decision) Priorizar a fonte técnica mais recente para valores divergentes, mesmo quando outra fonte for mais específica; registrar a divergência e a incerteza, sem calcular média.
- (assumption) A regra de recência só compara fontes com data verificável e aplicabilidade ao modelo; se não for possível identificar a fonte mais recente ou sua aplicabilidade, manter o campo indisponível.
- (decision by user) For materially conflicting applicable sources, prioritize the newest source even if it is less specific; record the conflict and uncertainty and do not average values. User answer: newest_source.
- (event) Self-validation pass 1 (coherence, updated): passed; the newest-applicable-source rule is explicit, metadata and didactic warning remain measurable, and unresolved date/applicability yields unavailable.
- (event) Self-validation pass 2 (preservation, updated): passed; the user-approved secondary-source policy, latest-source conflict decision, suggested research leads, VFR/day, RAB N and 30-model limits are represented in the spec or companion.
